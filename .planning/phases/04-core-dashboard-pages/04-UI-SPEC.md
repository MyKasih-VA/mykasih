## Page-by-Page Interaction Contracts

### PAGE-01: Voice Calls (`/voice-calls`)

**Layout:** Filter bar (full width) → Table (full width) → Pagination row

**Filter bar (one row, D-04):**
- Search input (placeholder: "Search by name or WA number...") — 300ms debounce before triggering fetch
- Date preset dropdown: All time | Today | This week | This month | Custom
- When "Custom" is selected: two `<input type="date">` fields appear inline (from + to), styled `bg-[var(--bg-surface)] border-[var(--bg-border)]`
- Language dropdown: All | BM | EN | Mixed
- Category dropdown: All categories | Eligibility | FAQ | Registration | Complaint | Merchant Lookup | Balance Check
- Outcome dropdown: All outcomes | Resolved | Escalated | Callback | Abandoned
- Export button (right-aligned in row): `bg-[var(--accent-primary)]` text white — triggers GET `/api/export/calls`

**Table columns (in order):** Channel | Caller | Category | Outcome | Duration | Time | (action — click row)

**Row click:** Opens TranscriptModal with `callId` — fetches `/api/calls/{id}/transcript`

**Pagination:** 25 rows per page. Prev/Next buttons below table. Total count shown: "Showing 1–25 of {total}"

**Loading state:** 8 skeleton rows (h-12) inside table body wrapper

**Empty state:** `Inbox` icon + "No voice calls yet" heading (14px semibold) + "Voice calls will appear here once SARA receives calls via WhatsApp." body (12px muted) — centered, py-16

**Error state:** Replace table with: "Unable to load calls. Check your connection and try again." — 14px, text-muted, centered

### PAGE-02: Chat Messages (`/chat-messages`)

**Layout:** Page heading row (count summary) → Table (full width) → Pagination row

**No filter bar** — page shows all chat sessions; search is available via the All Interactions page

**Table columns (D-08):** Channel (💬 badge) | WA Number | Intent badge | Messages | Outcome | Time | Ticket Ref

- Channel column: always shows `ChannelBadge` with channel=chat
- Intent badge: `IntentBadge` component using `color-mix` pattern
- Messages: integer count from `message_count` field, rendered as "{n} msgs"
- Ticket Ref: if `reference_no` exists, show as monospace link text (no navigation — display only for v1); if null, show "--"

**Row click:** Opens TranscriptModal (same as Voice Calls)

**Pagination:** 25 rows per page

**Loading state:** 8 skeleton rows

**Empty state:** `MessageSquare` icon + "No chat messages yet" + "WhatsApp conversations will appear here once the chatbot goes live." — py-16

**Error state:** "Unable to load chat messages. Check your connection and try again."

### PAGE-03: All Interactions (`/all-interactions`)

**Layout:** Channel toggle tabs → Filter bar (same as Voice Calls minus Language dropdown — language not meaningful for combined view) → Table → Pagination

**Channel toggle (D-13):** Shadcn Tabs component
- Tabs: [All | 📞 Voice | 💬 Chat]
- Switching tab sets `channel` filter param (empty | 'voice' | 'chat')
- Tab trigger active state: `bg-[var(--bg-surface)]` underline in `var(--accent-primary)`

**Table columns:** Channel | Caller / WA Number | Category | Outcome | Duration / Messages | Time
- Duration / Messages column: voice rows show seconds (`{n}s`), chat rows show message count (`{n} msgs`) — matches D-14

**Filter bar:** Search + Date preset + Category + Outcome + Export button (same layout as PAGE-01, without Language filter)

**Loading / empty / error:** Same pattern as Voice Calls with copy "No interactions found matching your filters."

### PAGE-04: Tickets (`/tickets`)

**Layout:** Column header row → 3-column kanban grid

**Kanban grid:** `grid grid-cols-3 gap-6`

**Column headers:**
- "Open" — `var(--status-red)` dot + label `text-xs font-semibold uppercase text-[var(--text-muted)]` + count badge
- "In Progress" — `var(--status-yellow)` dot + label + count badge
- "Resolved" — `var(--status-green)` dot + label + count badge

**Ticket card (D-02):**
```
┌─────────────────────────────────┐
│ TKT-2026-00001    [complaint]   │  ← ref no (mono) + category badge
│ 880512-**-****                  │  ← masked_ic (mono) or "--" if null
│ 2h ago                          │  ← relative time (text-xs muted)
│ ────────────────────────────── │
│ Status: [Open          ▼]       │  ← Shadcn Select
└─────────────────────────────────┘
```

- Card background: `var(--bg-surface)`, border: `var(--bg-border)`, rounded-lg
- Reference number: `font-mono text-xs text-[var(--text-primary)]`
- masked_ic: `font-mono text-xs text-[var(--text-muted)]`
- Category badge: same `color-mix` pattern as outcome badges — use `--status-yellow` for complaint, `--accent-teal` for faq, `--accent-primary` for merchant_lookup, `--status-green` for balance_check
- Relative time: `text-xs text-[var(--text-muted)]`
- Status Select: Shadcn Select, width full, options: Open | In Progress | Resolved

**Status change interaction (D-01, Pitfall 3):**
1. User selects new status from dropdown
2. Optimistic update — card moves to new column immediately in local state
3. PATCH `/api/tickets/{id}` fires in background
4. On PATCH failure: revert local state + show inline error toast "Status update failed. Please try again."

**Loading state:** 3 columns each with 3 skeleton cards (Card with `h-24`)

**Empty state (per column):** Dashed border box — "No {open/in-progress/resolved} tickets" — text-xs text-muted, centered, h-24

### PAGE-05: Beneficiaries (`/beneficiaries`)

**Layout:** Centered search panel (blank until search) → Profile view (appears after search returns result)

**Search-first state (D-10):**
- Vertically centered in viewport (above the fold)
- Search heading: "Find a Beneficiary" — `text-xl font-semibold text-[var(--text-primary)]`
- Subtext: "Search by WhatsApp number or name" — `text-sm text-[var(--text-muted)]`
- Input: full-width max-w-lg, placeholder "+601X-XXX-XXXX or name", with Search button (icon: `Search` from Lucide) — minimum 2 characters before fetch fires
- Triggers GET `/api/beneficiaries?query={value}`

**Search loading state:** Spinner (Lucide `Loader2` with `animate-spin`) inside Search button

**No results state:** Below search bar — `UserX` icon + "No beneficiary found" + "Try a different WA number or name." — py-12

**Profile view (D-11):** Slides in below search bar after result

```
┌──────────────────────────────────────────────────────┐
│ [avatar initial]  Siti Aishah          +60123456789  │  ← name + WA number
│                   Last seen: 2h ago                  │
└──────────────────────────────────────────────────────┘

Interaction History (N)
[full-width table: Channel | Category | Outcome | Duration/Msgs | Time]
[click row → TranscriptModal]

Ticket History (N)
[full-width table: Ref No. | Category | masked IC | Status | Time]
```

- Avatar: 40px circle, `bg-[var(--accent-primary)]`, white initial letter, `text-sm font-semibold`
- Profile header: `bg-[var(--bg-surface)]` card, padding 24px
- Section headings: `text-base font-semibold text-[var(--text-primary)]` + count in muted text
- Tables: same Shadcn Table pattern as other pages
- masked_ic in Ticket History: `font-mono text-xs`

**Empty interaction/ticket sections:** `Inbox` icon + "No interactions" or "No tickets" — `text-xs text-muted`

## Data Masking Rules

All components rendering ticket data must follow these rules:

- `masked_ic` field: render as-is from DB (already stored as `880512-**-****`) — use `font-mono text-xs`
- `wa_number`: display as-is — not PDPA-sensitive per schema
- `caller_name`: display as-is — not PDPA-sensitive per schema
- Raw IC: never derive, never compute, never display — any IC handling happens in API layer only
- Fallback for null `masked_ic`: render `--` (not empty string)

## Anti-Patterns (Do Not)

| Pattern | Rule |
|---------|------|
| Hardcoded hex colors | Never `className="text-[#43A047]"` — always `text-[var(--chart-voice)]` |
| Plain-text IC in UI | Tickets kanban renders `masked_ic` only — never raw IC |
| `next/router` import | Use `next/navigation` in App Router |
| `params` without await | Dynamic route handlers must `const { id } = await params` |
| Missing `'use client'` | All 5 pages use `useLanguage()` — must be client components |
| Fetch without `.ok` check | Every fetch needs error handling + error state |
| `useSearchParams()` without Suspense | Use `useState` for filter state — not URL params |
| Search without debounce | 300ms debounce on all text search inputs before API call |
| Kanban without optimistic update | Move card in local state before PATCH returns |
| TranscriptModal fetching on every render | Depend on `[callId, open]` — only fetch when `open === true` |
| `Badge` component for intent/outcome | Use `<span>` with inline `color-mix` style — matches established project pattern |
