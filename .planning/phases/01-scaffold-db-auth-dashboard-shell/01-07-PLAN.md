<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> /api/seed/data | Admin-only endpoint; one-time use for demo setup |
| API -> Supabase (service role) | Bypasses RLS for bulk insert — acceptable for seed |
| Supabase SQL Editor | Manual migration run by user |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-01 | Elevation of Privilege | /api/seed/data | mitigate | Admin role check required; idempotency guard prevents repeat execution |
| T-07-02 | Tampering | Seed data | accept | Seed data is demo-only (is_test=true, DEMO_ prefix); flushed before go-live |
| T-07-03 | Information Disclosure | Seed user emails | accept | Test emails (admin@mykasih.com etc.) are not real user emails; replaced in production |
| T-07-04 | Denial of Service | Bulk insert | mitigate | Idempotency guard (409 if already seeded) prevents accidental re-run; single-use endpoint |
</threat_model>
