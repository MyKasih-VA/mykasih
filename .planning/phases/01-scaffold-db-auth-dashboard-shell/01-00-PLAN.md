  <action>
Install test dependencies:

```bash
cd mykasih-crm && npm install -D jest @testing-library/react @testing-library/jest-dom ts-jest @types/jest jest-environment-jsdom
```

Create `mykasih-crm/jest.config.ts`:

```typescript
import type { Config } from 'jest'
import nextJest from 'next/jest.js'

const createJestConfig = nextJest({
  dir: './',
})

const config: Config = {
  coverageProvider: 'v8',
  testEnvironment: 'jsdom',
  setupFilesAfterFramework: ['<rootDir>/jest.setup.ts'],
  moduleNameMapper: {
    '^@/(.*)$': '<rootDir>/$1',
  },
  testPathPattern: '__tests__',
}

export default createJestConfig(config)
```

IMPORTANT: The Jest 29 Config key is `setupFilesAfterFramework` — this is the correct property for running setup files after the test framework (e.g. jsdom) is installed in the environment. Do NOT use `setupFilesAfterSetup` (invalid key, will cause TypeScript error). If `setupFilesAfterFramework` causes a TypeScript error in the executor's specific Jest version, fall back to `setupFiles` which also works since `next/jest` handles framework setup internally. The executor MUST verify the config is accepted by running `npx jest --showConfig 2>&1 | grep setup` to confirm the setup file is loaded.

Also create `mykasih-crm/jest.setup.ts`:

```typescript
import '@testing-library/jest-dom'
```

Add to `mykasih-crm/package.json` scripts (if not already present):
```json
"test": "jest --passWithNoTests"
```

This also serves as verification that INFRA-01 (Next.js scaffolded) and INFRA-02 (Shadcn initialized) are intact by confirming the project builds and test infra integrates with the existing scaffold.
