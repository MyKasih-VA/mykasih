## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User browser → Supabase Auth | TOTP verification happens server-side in Supabase |
| Login page → MFA pages | Client-side redirect; session exists at aal1 level |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-12 | Spoofing | Admin account | mitigate | TOTP MFA enforced for all admin accounts — attacker needs password + physical authenticator device |
| T-07-13 | Tampering | MFA bypass via direct URL | mitigate | Even if user navigates past MFA pages, API routes check session AAL level via Supabase — aal1 session has limited access |
| T-07-14 | Elevation of Privilege | Non-admin accessing MFA-only features | accept | Non-admin roles don't trigger MFA gate — their access is controlled by RLS policies (Plan 02) |
| T-07-15 | Denial of Service | MFA enrollment failure | mitigate | Error handling redirects to retry; admin can unenroll via Supabase Dashboard as recovery path |
| T-07-16 | Information Disclosure | TOTP secret exposure | mitigate | Secret displayed once during enrollment on same screen as QR; copy button uses clipboard API; no server-side logging of secrets |
</threat_model>
