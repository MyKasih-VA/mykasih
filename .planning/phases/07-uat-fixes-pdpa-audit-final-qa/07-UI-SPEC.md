## Spacing Scale

Declared values (multiples of 4 only — 8-point grid):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline icon padding |
| sm | 8px | Input internal horizontal padding (compact) |
| md | 16px | Default element spacing, card internal gaps |
| lg | 24px | Card padding (login card uses `p-8` = 32px — see exception) |
| xl | 32px | Card padding (login card pattern: `p-8`) |
| 2xl | 48px | Major section breaks within a page |
| 3xl | 64px | Page-level vertical centering offsets |

Exceptions:
- Login card uses `p-8` (32px) — matches existing login/page.tsx. MFA screens MUST match this exactly.
- Input height: 44px (`h-11`) — set by existing login form inputs. Touch-target compliant.
- Button height: 44px (`h-11`) — set by existing login form button. Carry forward to MFA screens.

## New UI Surfaces — Phase 7

Phase 7 adds exactly two new pages and modifies one existing page. All are auth-flow screens.

### Surface 1: MFA Enrollment Page (`/login/mfa-enroll`)

**Layout:** Identical structure to `login/page.tsx` — centered card on `--bg-primary` background, max-w-[400px], logo above card.

**Card contents (top to bottom):**
1. Section heading: "Set Up Two-Factor Authentication" — text-base font-semibold, `--text-primary`
2. Body copy: "Scan the QR code below with your authenticator app (Google Authenticator or Authy), then enter the 6-digit code to confirm." — text-sm, `--text-muted`, line-height 1.5
3. QR code image: rendered as `<img src={qrCodeDataUrl} />` from `qrcode` npm package output. Size: 180x180px, centered. Background: white (`#FFFFFF`) — QR codes require high contrast; the QR image itself is white-background, contained within the dark card.
4. Secret fallback: "Can't scan? Enter this code manually:" label (text-xs, `--text-muted`) + secret string in `font-mono text-sm --text-primary` with copy-to-clipboard icon (Lucide `Copy` 14px).
5. TOTP code input: 6-digit numeric input, `h-11 text-center text-lg tracking-widest`, same style as login inputs (`--bg-primary` fill, `--bg-border` border, `--accent-teal` focus ring). Placeholder: "000000". `inputMode="numeric"` `maxLength={6}` `pattern="[0-9]{6}"`.
6. Submit button: "Verify & Enable MFA" — full width, `h-11`, `--accent-primary` background, `--text-primary` text, font-semibold. Shows `<Loader2 size={16} className="animate-spin" />` during in-flight verification.
7. Error display: below button, text-xs, `--status-red`, `role="alert"`.

**Interaction states:**
- Initial state: "Loading QR code..." skeleton (Skeleton component, 180x180px) while `enroll()` call is in-flight.
- QR displayed: input enabled, button enabled.
- Submitting: input disabled, button disabled + spinner.
- Error: input re-enabled, error text shown below button, input cleared.
- Success: no separate success page — `router.push('/')` immediately on `verify()` success.

**Anti-pattern to avoid:** Do NOT navigate away from this page between `enroll()` and `verify()`. QR code and verification input MUST be on the same screen. Source: RESEARCH.md Pitfall 3.

### Surface 2: MFA Challenge Page (`/login/mfa-challenge`)

**Layout:** Identical structure to `login/page.tsx` — centered card on `--bg-primary`, max-w-[400px], logo above.

**Card contents (top to bottom):**
1. Section heading: "Two-Factor Authentication" — text-base font-semibold, `--text-primary`
2. Body copy: "Enter the 6-digit code from your authenticator app." — text-sm, `--text-muted`
3. TOTP code input: same spec as enrollment input above.
4. Submit button: "Verify Code" — same style as "Sign In" button.
5. Error display: below button, text-xs, `--status-red`, `role="alert"`.

**Interaction states:**
- Loading: challenge is initialized via `useEffect` on mount. Show spinner centered in card body while `listFactors()` + `challenge()` calls complete.
- Ready: input focused, button enabled.
- Submitting: input disabled, button disabled + spinner.
- Error (wrong code): "Invalid code. Please check your authenticator app and try again." — input cleared, re-focused.
- Error (no factor found): redirect to `/login` — this should not happen in normal flow.

### Surface 3: Login Page Modification (`/login/page.tsx`)

**What changes:** After `signInWithPassword()` succeeds, before role-based redirect, add admin MFA gate. No visible UI change for non-admin users. For admin users:
- If MFA not enrolled: redirect to `/login/mfa-enroll` (no visible change on login page itself).
- If MFA enrolled but session is aal1: redirect to `/login/mfa-challenge` (no visible change on login page itself).

No new visual elements added to login/page.tsx itself.

## Accessibility Contract

MFA screens must meet the following accessibility requirements (consistent with WCAG 2.1 AA):

| Requirement | Implementation |
|-------------|----------------|
| Error messages announced to screen readers | `role="alert"` on error `<p>` — matches existing login/page.tsx pattern |
| Loading state announced | Button `aria-busy="true"` when `loading === true` |
| TOTP input labelled | `<label htmlFor="totp-code">` paired with input `id="totp-code"` |
| QR code described | `<img alt="Scan this QR code with your authenticator app" />` |
| Input type | `type="text" inputMode="numeric"` (not `type="number"` — avoids spinners) |
| Focus management | Auto-focus TOTP input on page load for both enroll and challenge screens |
| Keyboard navigation | All interactive elements reachable via Tab key — native HTML elements, no custom components needed |
