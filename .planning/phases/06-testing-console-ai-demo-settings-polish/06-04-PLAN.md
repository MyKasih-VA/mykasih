```typescript
export const runtime = 'nodejs'
```

**GET handler:**
1. Auth guard: same pattern as `export/calls/route.ts`:
   - `const supabase = await createClient()` from `@/lib/supabase/server`
   - `supabase.auth.getUser()` -> check user exists
   - Query `users` table for role -> must be `'admin'`
   - Return 401 if no user, 403 if non-admin
2. Query: `supabase.from('settings').select('key, value')`
3. Transform to flat object: `Object.fromEntries((data ?? []).map(r => [r.key, r.value]))`
4. Apply defaults for any missing keys:
   ```typescript
   const DEFAULTS: Record<string, string> = {
     agent_hours_start: '08:00',
     agent_hours_end: '17:00',
     notification_email: '',
     data_retention_days: '90',
   }
   const result = { ...DEFAULTS, ...Object.fromEntries((data ?? []).map(r => [r.key, r.value])) }
   ```
5. Return `Response.json(result)`

**PATCH handler:**
1. Same auth guard as GET (admin-only).
2. Parse body: `const body = await request.json()` — expect `{ settings: Array<{ key: string, value: string }> }`
3. Validate:
   - `agent_hours_start` and `agent_hours_end`: must match `/^\d{2}:\d{2}$/` (HH:MM format)
   - `notification_email`: if non-empty, must contain `@` (basic email check)
   - `data_retention_days`: must be a parseable positive integer (`parseInt(value, 10) > 0`)
   - Return 400 with descriptive error if validation fails
4. Upsert each key-value pair:
   ```typescript
   for (const { key, value } of body.settings) {
     const { error } = await supabase
       .from('settings')
       .upsert({ key, value, updated_at: new Date().toISOString() }, { onConflict: 'key' })
     if (error) {
       return Response.json({ error: `Failed to save ${key}` }, { status: 500 })
     }
   }
   ```
5. Return `Response.json({ success: true })`

Wrap both handlers in try/catch. Return 500 with generic error on unexpected failures.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> /api/settings | Admin submits settings values |
| /api/settings -> Supabase | Server writes to settings table |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-10 | Spoofing | /api/settings | mitigate | Admin-only role check via supabase.auth.getUser() + users table role lookup. Returns 401 for unauthenticated, 403 for non-admin. Pattern verified from export/calls route. |
| T-06-11 | Tampering | PATCH /api/settings input | mitigate | Validate HH:MM format with regex for agent hours, email format check for notification_email, positive integer check for data_retention_days. Return 400 on invalid input. |
| T-06-12 | Elevation of Privilege | Settings API access | mitigate | Only 'admin' role can read/write settings. RLS on settings table restricts to service_role. Non-admin roles (mykasih, qmedia, supervisor) get 403. |
| T-06-13 | Information Disclosure | Webhook URLs in client | accept | Webhook URLs are constructed from NEXT_PUBLIC_APP_URL env var (public domain) + known API paths. These URLs are not secrets — they need to be configured in external services (ElevenLabs, Meta WA). Displaying them is the purpose of Card 4. |
</threat_model>
