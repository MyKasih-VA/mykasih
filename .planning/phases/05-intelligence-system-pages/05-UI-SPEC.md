Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline tag padding, badge px |
| sm | 8px | Compact row padding, between icon and label |
| md | 16px | Default card padding, form field gap, button px |
| lg | 24px | Card internal padding (p-6), section spacing |
| xl | 32px | Between page sections, chart container margin |
| 2xl | 48px | Page top padding, empty state vertical center |
| 3xl | 64px | Full empty-state container minimum height |

Exceptions:
- Heatmap cells: 28px × 28px fixed size — narrowest responsive grid that fits 24 hour rows without overflow at 1280px viewport
- Skeleton row height: 20px (h-5) — matches table row text baseline
- Touch targets (switch toggle): 44px minimum tap area — WCAG 2.5.5

## Typography

All text uses `var(--font-sans)` (Inter). Monospace (`var(--font-mono)`, JetBrains Mono) reserved for code snippets, webhook URL display, and reference numbers only.

| Role | Size | Weight | Line Height | CSS Class Pattern | Usage |
|------|------|--------|-------------|-------------------|-------|
| Caption / Label | 12px (text-xs) | 400 Regular | 1.5 | `text-xs text-[var(--text-muted)]` | Table column headers, stat card labels, badge text, form field hints |
| Body | 14px (text-sm) | 400 Regular | 1.5 | `text-sm text-[var(--text-primary)]` | Table cell content, modal body, KB entry text, form input values |
| Card title / Section heading | 14px (text-sm) | 600 Semibold | 1.4 | `text-sm font-semibold text-[var(--text-primary)]` | Card titles, section headings within pages, modal titles — standard shadcn card title pattern |

Weights in use: Regular (400) and Semibold (600) only. Bold (700) is reserved for numeric stat values inside StatCard — not introduced on new elements.

## Page-by-Page Interaction Contract

### Analytics Page (`/analytics`)

**Layout:** Full-width page with sticky period selector bar at top, then 2×2 chart grid, then category breakdown table below.

**Primary focal point:** The Volume Bar Chart (top-left of the 2×2 grid) is the primary visual anchor; stat cards above serve as supporting context.

**Period Selector:**
- Shadcn `Tabs` for preset options: "Today" | "This Week" | "This Month" | "Last 3 Months"
- "Custom" option opens a Shadcn `Popover` containing a `Calendar` date range picker
- Active preset tab uses `var(--accent-primary)` background; inactive tabs use `var(--bg-surface)` border
- On change: re-fetch `/api/analytics/charts?period={preset}&from={ISO}&to={ISO}`

**Chart Grid (2 columns on desktop, 1 column on mobile):**
1. Volume Bar Chart — Recharts `BarChart`, stacked bars, voice (`--chart-voice`) and chat (`--chart-chat`), 7 or 30 day labels on X axis
2. CSAT Trend — Recharts `LineChart`, single line in `--accent-primary`, Y axis 1–5, reference line at 3.5 (dashed, `--text-muted`)
3. Language Pie — Recharts `PieChart`, 3 segments: BM (`--accent-primary`), EN (`--accent-teal`), Mixed (`--status-yellow`), Recharts `Legend` below
4. Peak Heatmap — CSS grid (7 col × 24 row), each cell `28px × 28px`, header row = Mon–Sun labels, header col = 00:00–23:00 labels, cell color: `color-mix(in srgb, var(--accent-primary) {intensity}%, var(--bg-surface))` where intensity = `Math.round((count / maxCount) * 100)`; minimum intensity 5% so empty cells remain faintly distinct from background; tooltip on hover shows "Mon 14:00 — 23 interactions"

**Category Breakdown Table:**
- Shadcn `Table` with columns: Category | Voice | Chat | Total | % of Total
- No bar embellishment — plain numbers
- Sorted by Total descending
- Percentage formatted as "12.4%"

**Loading state:** All 4 chart cards show `Skeleton` at chart height (240px) while fetching

**Empty state (CSAT chart, no ratings yet):** Centered `TrendingUp` Lucide icon + "No CSAT ratings yet" heading + "Ratings appear after calls are scored" body — no placeholder chart

**Stat row above charts:** 4 `StatCard` components — Total Interactions, Avg CSAT, Resolution Rate, Peak Hour — same component as Dashboard home

### Knowledge Base Page (`/knowledge-base`)

**Layout:** Page header row (title + "Add Entry" button + BM/EN toggle + "Sync to ElevenLabs" button), then full-width `Table`.

**Table columns:** Active (Switch) | Category | Question | Answer | Actions (Edit, Delete)
- "Question" and "Answer" columns switch between BM and EN content based on BM/EN toggle state — not a filter, both rows always exist
- "Active" column: inline Shadcn `Switch` — fires PATCH `/api/kb/[id]` with `{ is_active: boolean }` immediately on toggle, no save needed
- Active row: normal opacity; inactive row: `opacity-50` to signal disabled state

**BM/EN toggle:** Shadcn `Tabs` (two items: "BM" | "EN"), not a full filter — changes column header label and which language fields display

**Sync to ElevenLabs button:**
- Default state: `var(--accent-primary)` background, "Sync to ElevenLabs" label, `RefreshCw` icon left
- Loading state: spinner replaces icon, button disabled, label "Syncing..."
- Success: Shadcn `toast` (sonner) — "Knowledge base synced to ElevenLabs" — green variant
- Error: Shadcn `toast` — "Sync failed: {error message}. Try again." — destructive variant

**Add/Edit Modal:** Shadcn `Dialog`
- Trigger: "Add Entry" button (header) or "Edit" row action
- Title: "Add KB Entry" / "Edit KB Entry"
- Fields in order: Category (Shadcn `Select` — options from kb categories), Question (BM) `Textarea`, Answer (BM) `Textarea`, Question (EN) `Textarea`, Answer (EN) `Textarea`, Active toggle (Shadcn `Switch` with label)
- CTA: "Save Entry" (`var(--accent-primary)`) | "Discard changes" (ghost)
- On save: POST `/api/kb` (add) or PATCH `/api/kb/[id]` (edit), close modal, refresh table

**Delete flow:** Inline "Delete" button → inline `AlertDialog` confirmation: "Delete this KB entry? This cannot be undone." with "Delete" (destructive red) and "Keep entry" buttons → DELETE `/api/kb/[id]`

**Pagination:** 25 rows per page, Shadcn pagination controls at table bottom

**Loading state:** 5 `Skeleton` rows at `h-10` height

**Empty state:** `BookOpen` Lucide icon + "No knowledge base entries" + "Add your first entry to get started." + "Add Entry" button

### Staff Management Page (`/staff`)

**Layout:** Page header row (title + "Invite Staff" button), then full-width `Table`.

**Table columns:** Name | Email | Role | Status | Last Login | Actions (Edit Role, Remove)
- "Status" column: "Active" badge (`--status-green`) or "Pending" badge (`--status-yellow`) depending on whether invite has been accepted
- "Last Login" column: relative time format ("3 days ago", "Never") — use `formatRelativeTime` helper from CallsTable.tsx
- Pending rows show "Resend invite" action button instead of "Edit Role"

**Invite Staff Modal:** Shadcn `Dialog`
- Trigger: "Invite Staff" button (header)
- Title: "Invite Staff Member"
- Fields: Name (`Input`), Email (`Input`, type=email), Role (`Select` — options: admin, mykasih, qmedia, supervisor)
- CTA: "Send Invite" (`var(--accent-primary)`) | "Discard" (ghost)
- On submit: POST `/api/staff/invite` → Supabase `inviteUserByEmail()` server-side; success toast "Invite sent to {email}"; error toast "Failed to send invite. Try again."

**Edit Role Modal:** Shadcn `Dialog` (minimal — role change only)
- Title: "Change Role — {name}"
- Fields: Role (`Select`)
- CTA: "Update Role" (`var(--accent-primary)`) | "Keep current role" (ghost)

**Remove Staff flow:** "Remove" row action → `AlertDialog` confirmation: "Remove {name}? They will lose access immediately." → "Remove" (destructive red) + "Keep member" → DELETE `/api/staff/[id]`; success toast "Staff member removed."

**Pagination:** 25 rows per page

**Loading state:** 5 `Skeleton` rows at `h-10` height

**Empty state:** `Users` Lucide icon + "No staff members" + "Invite your first team member to get started."

### Integrations Page (`/integrations`)

**Layout:** Page header (title + "Refresh Status" button), then 3-column grid of status cards on desktop (2-column on tablet, 1-column on mobile), then Database section below (existing merchant seed card preserved here — not moved to Settings).

**Integration Status Card structure (per card):**
- Icon (service logo via Lucide or text badge) + Service name (text-sm semibold)
- Status badge: "ok" → green badge (`--status-green`); "error" → red badge (`--status-red`); "pending" → yellow badge (`--status-yellow`); "ready" → green badge
- Status label text: "Connected" | "Error" | "Pending Approval" | "Ready"
- Description line (text-xs muted): one-line description of what this integration does
- Action button (secondary, outlined): see per-card spec below
- Card background: `var(--bg-surface)`, border: `var(--bg-border)`, rounded-lg, p-6

**Per-card action buttons:**
- ElevenLabs: "Test Connection" — fires inline GET to `/api/integrations/status`, updates only this card's badge; loading spinner on button during check
- Meta WA: "Copy Webhook URL" — writes `/api/webhook/chat` full URL to clipboard; success toast "Webhook URL copied"
- n8n: "Open n8n" — external link, opens `N8N_BASE_URL` in new tab; `ExternalLink` icon right
- Supabase: "View Project" — external link to Supabase dashboard; `ExternalLink` icon right
- Anam AI: "Open Demo" — internal `<Link href="/demo">` with `ArrowRight` icon right

**Refresh Status button (page header):** Triggers GET `/api/integrations/status` for all cards; spinner on button while loading; updates all card badges on response

**Database section (below integration cards):**
- Section heading "Database" (text-sm semibold, `--text-muted`)
- Existing merchant seed card preserved as-is from Phase 1 implementation

**Loading state (initial page load):** All 5 cards show `Skeleton` at card height (120px)

### Live Monitor Page (`/live-monitor`)

**Layout:** Page header (title + last-refreshed timestamp + "Refresh Now" button), then 2-column split: Voice Sessions (left) and Chat Sessions (right).

**Auto-refresh:** `setInterval` every 10 000ms calling GET `/api/live-monitor/status`. Pauses when `document.visibilityState === 'hidden'`. Resumes on `visibilitychange` event.

**Last-refreshed timestamp:** "Updated {N}s ago" — counter ticks up every second from last fetch time; resets to "Updated just now" immediately after each successful fetch. Text-xs muted, positioned inline right of "Refresh Now" button.

**Voice Sessions column:**
- Section header: `Phone` Lucide icon + "Active Voice Sessions" label + live count badge (`--chart-voice` background, white text)
- Per-session card: `var(--bg-surface)` border card
  - Row 1: Caller name (or "Unknown Caller" if null) — text-sm semibold
  - Row 2: Phone number (wa_number) — text-xs muted
  - Row 3: Duration live counter "● 2m 34s" (green dot `--status-green`, timer increments client-side from session start)
  - Row 4: Language badge (BM / EN / Mixed) using existing `ChannelBadge`-style pattern
- Empty state: `PhoneOff` icon + "No active voice sessions" + "Live sessions appear here when calls are in progress."

**Chat Sessions column:**
- Section header: `MessageSquare` Lucide icon + "Active Chat Sessions" label + live count badge (`--chart-chat` background, white text)
- Per-session card: `var(--bg-surface)` border card
  - Row 1: Beneficiary WA number — text-sm semibold
  - Row 2: Current intent badge (using existing `IntentBadge` pattern from Phase 4)
  - Row 3: Session age "Started 4m ago" — text-xs muted, relative time
  - Row 4: Message count "8 messages" — text-xs muted
- Empty state: `MessageSquareOff` icon + "No active chat sessions" + "Live sessions appear here when WhatsApp conversations are in progress."

**Loading state (initial fetch):** 3 skeleton cards per column at h-24

**Error state (fetch failed):** Single error banner across full width: "Could not load live sessions. Check your connection and try again." with "Try again" button

## Accessibility

- All modal `Dialog` components: focus trapped on open, `Escape` closes, `aria-labelledby` pointing to `DialogTitle`
- All tables: `<th scope="col">` on header cells
- Switch toggles: `aria-label` with descriptive text (e.g., "Toggle active state for {entry question}")
- Heatmap cells: `aria-label="{day} {hour} — {count} interactions"` on each cell
- Live Monitor auto-refresh: `aria-live="polite"` region wrapping session counts so screen readers announce count changes
- Color is never the sole indicator of status — all status badges include text label alongside color
- Destructive `AlertDialog` buttons: focus lands on dismiss button by default (safer default), not "Delete"/"Remove"
