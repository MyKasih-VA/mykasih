**IMPORTANT:** Read AGENTS.md reference — check `node_modules/next/dist/docs/` for any Next.js 16 breaking changes before writing route handlers.

**Route 1 — `/api/kb/route.ts` (GET + POST):**

GET handler:
- Import `createClient` from `@/lib/supabase/server`
- Auth check: `supabase.auth.getUser()` — return 401 if no user
- Query: `supabase.from('kb_entries').select('*').order('last_updated', { ascending: false })`
- Return `{ entries: data }`

POST handler:
- Auth check same as GET
- Parse body: `{ category: string, question_bm: string, question_en: string, answer_bm: string, answer_en: string, is_active: boolean }`
- Validate: all text fields must be non-empty strings after trim
- Insert: `supabase.from('kb_entries').insert({ category, question_bm, question_en, answer_bm, answer_en, is_active, updated_by: user.email }).select().single()`
- Return 201 with `{ entry: data }`
- On error: return 400 with `{ error: 'message' }`

**Route 2 — `/api/kb/[id]/route.ts` (PATCH + DELETE):**

PATCH handler:
- Auth check
- Extract `id` from route params (follow Next.js 16 pattern — check docs for dynamic route param extraction)
- Parse body: partial update — any subset of `{ category, question_bm, question_en, answer_bm, answer_en, is_active }`
- Update: `supabase.from('kb_entries').update({ ...fields, last_updated: new Date().toISOString(), updated_by: user.email }).eq('id', id).select().single()`
- Return `{ entry: data }`

DELETE handler:
- Auth check
- Extract `id` from route params
- Delete: `supabase.from('kb_entries').delete().eq('id', id)`
- Return `{ success: true }`

**Route 3 — `/api/kb/sync/route.ts` (POST):**

Per D-12 and D-13:
- Auth check (must be authenticated staff)
- Fetch all active KB entries: `supabase.from('kb_entries').select('*').eq('is_active', true)`
- Format entries into a knowledge document string:
  ```
  Q (BM): {question_bm}\nA (BM): {answer_bm}\nQ (EN): {question_en}\nA (EN): {answer_en}\n\n
  ```
  Concatenate all entries.
- Call ElevenLabs Agent API:
  ```typescript
  const response = await fetch(
    `https://api.elevenlabs.io/v1/convai/agents/${process.env.ELEVENLABS_AGENT_ID}`,
    {
      method: 'PATCH',
      headers: {
        'xi-api-key': process.env.ELEVENLABS_API_KEY!,
        'Content-Type': 'application/json',
      },
      body: JSON.stringify({
        conversation_config: {
          agent: {
            prompt: {
              knowledge_base: knowledgeDocument,
            },
          },
        },
      }),
    }
  )
  ```
- If response.ok: return `{ success: true }`
- If response NOT ok: extract error message, return `{ error: errorMessage }` with status 502
- Wrap entire flow in try/catch — on catch, return 500 with `{ error: 'Internal server error' }`

Note: `ELEVENLABS_API_KEY` and `ELEVENLABS_AGENT_ID` are server-side only env vars — they must NEVER be sent to the client. This route runs server-side only.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> /api/kb/* | Authenticated staff mutating KB data |
| server -> ElevenLabs API | KB sync pushes knowledge to external voice agent |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-KB-01 | Spoofing | /api/kb/* routes | mitigate | Auth check via `supabase.auth.getUser()` at entry of every handler — reject 401 if no session |
| T-5-KB-02 | Information Disclosure | /api/kb/sync | mitigate | `ELEVENLABS_API_KEY` used only server-side in route.ts; never exposed to client. Key accessed via `process.env` which is not bundled client-side in Next.js |
| T-5-KB-03 | Tampering | KB entry fields | accept | Text fields are FAQ content managed by authenticated staff. No PII in KB entries. XSS mitigated by React's default escaping. Low risk. |
| T-5-KB-04 | Denial of Service | /api/kb/sync | accept | Sync is manual button press by authenticated user. Rate limiting not needed for internal admin tool at current scale. |
</threat_model>
