**Critical — Service Role Client:**
Per D-21, staff management requires Supabase Admin methods (`inviteUserByEmail`, `deleteUser`) which are only available on a client created with `@supabase/supabase-js` directly (NOT `@supabase/ssr`). Copy the pattern from `lib/chatbot/session-manager.ts`:

```typescript
import { createClient as createServiceClient } from '@supabase/supabase-js'

function getAdminClient() {
  return createServiceClient(
    process.env.NEXT_PUBLIC_SUPABASE_URL!,
    process.env.SUPABASE_SERVICE_ROLE_KEY!
  )
}
```

**All routes must enforce admin-only access:**
```typescript
// At top of every handler:
const supabase = await createClient() // @supabase/ssr client for auth check
const { data: { user } } = await supabase.auth.getUser()
if (!user) return NextResponse.json({ error: 'Unauthorized' }, { status: 401 })

const { data: userData } = await supabase.from('users').select('role').eq('id', user.id).single()
if (userData?.role !== 'admin') return NextResponse.json({ error: 'Forbidden — admin only' }, { status: 403 })
```

**Route 1 — `/api/staff/route.ts` (GET):**
- Admin check (as above)
- Query: `supabase.from('users').select('id, email, name, role, created_at, last_login').order('created_at', { ascending: false })`
- For each user, determine status: if `last_login` is null, status = 'pending'; else status = 'active'
- Return `{ users: data.map(u => ({ ...u, status: u.last_login ? 'active' : 'pending' })) }`

**Route 2 — `/api/staff/invite/route.ts` (POST):**
- Admin check
- Parse body: `{ name: string, email: string, role: 'admin' | 'mykasih' | 'qmedia' | 'supervisor' }`
- Validate: email must be non-empty valid email, name non-empty, role must be one of the 4 valid values
- Step 1: Use admin client to invite: `const adminClient = getAdminClient(); await adminClient.auth.admin.inviteUserByEmail(email, { data: { name, role } })`
- Step 2: Insert into users table: `await supabase.from('users').insert({ email, name, role }).select().single()`
  - Note: if user already exists in users table (email unique constraint), return 409 with `{ error: 'User with this email already exists' }`
- Return 201 with `{ user: data }`
- On inviteUserByEmail error: return 500 with `{ error: errorMessage }`

**Route 3 — `/api/staff/[id]/route.ts` (PATCH + DELETE):**

PATCH handler:
- Admin check
- Extract `id` from route params
- Parse body: `{ role: 'admin' | 'mykasih' | 'qmedia' | 'supervisor' }`
- Validate role value
- Update: `supabase.from('users').update({ role }).eq('id', id).select().single()`
- Return `{ user: data }`

DELETE handler:
- Admin check
- Extract `id` from route params
- Step 1: Get user email from users table: `supabase.from('users').select('email').eq('id', id).single()`
- Step 2: Find auth user by email and delete from Supabase Auth:
  ```typescript
  const adminClient = getAdminClient()
  // List auth users to find the one matching this email
  const { data: authUsers } = await adminClient.auth.admin.listUsers()
  const authUser = authUsers.users.find(u => u.email === userEmail)
  if (authUser) {
    await adminClient.auth.admin.deleteUser(authUser.id)
  }
  ```
- Step 3: Delete from users table: `supabase.from('users').delete().eq('id', id)`
- Return `{ success: true }`

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> /api/staff/* | Admin user managing staff accounts |
| server -> Supabase Auth Admin | Service role key used for user management |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-Admin-01 | Elevation of Privilege | /api/staff/* routes | mitigate | Every route checks `users.role === 'admin'` after auth. Non-admin gets 403 Forbidden. Role check reads from `users` table, not from JWT claims (which could be stale). |
| T-5-Admin-02 | Information Disclosure | SUPABASE_SERVICE_ROLE_KEY | mitigate | Service role key accessed only in server-side API route handlers via `process.env`. Never imported in client components. Never sent in API responses. |
| T-5-Admin-03 | Spoofing | Staff invite | mitigate | `inviteUserByEmail` only callable from admin-checked server route. Email invite is Supabase-managed — no admin-set passwords. User must accept invite via email link. |
| T-5-Admin-04 | Tampering | Role assignment | mitigate | Role value validated against enum ['admin', 'mykasih', 'qmedia', 'supervisor'] server-side before write. Invalid values rejected with 400. |
</threat_model>
